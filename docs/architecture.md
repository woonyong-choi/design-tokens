# 아키텍처

design-tokens는 여러 소비자가 공유하는 토큰, 아이콘, CSS, 정적 HTML 구성 요소와 브라우저 동작의 정본이다. 값과 UI 구조는 이 저장소에서 정의하고 소비자는 콘텐츠와 서비스 정책을 연결한다.

## 코드 지도

| 위치 | 책임 |
|---|---|
| `tokens/` | 공통 기본값과 다크 모드의 의미 값 차이 |
| `styles/`, `assets/` | 공통 웹·도표 CSS와 아이콘·자산 |
| `ui/` | 신뢰 경계가 있는 HTML 조각·패턴·레이아웃과 공통 런타임 |
| `scripts/lib/` | 토큰 참조, CSS 평탄화와 생성 |
| `scripts/build.mjs` | 정본을 읽어 배포물을 만들거나 일치를 검사 |
| `scripts/export.mjs` | 소비자 사본을 검증하고 완성본을 교체 |
| `dist/` | 커밋하는 생성물. 수동 수정 금지 |
| `test/` | 참조·대비·구성 요소·산출물·축소 계약 검사 |

## 한 방향의 생성

`tokens`, `styles`, `assets`, `ui`에서 `dist`를 생성하고, 내보내기를 거쳐 소비자의 vendor 폴더로 전달한다. 소비자의 정적 빌드는 페이지에 쓰인 CSS와 스크립트를 축소한다. 소비자가 만든 페이지나 축소 파일을 정본으로 역수입하지 않는다.

토큰은 DTCG의 `$type`, `$value`와 경로 참조를 사용한다. 색은 hex 문자열이고 치수·시간은 값과 단위를 가진 객체다. DTCG 색 객체 전체를 구현했다고 표시하지 않는다.

공통 manifest는 배포 파일과 내용 해시를 기록한다. 내보내기 전 기존 해시를 확인하므로 소비자가 고친 파일은 자동 갱신으로 덮어쓰지 않는다. 검증 뒤 이전 배포에서 제거된 파일과 빈 폴더를 먼저 정리하므로 같은 경로가 파일에서 폴더로 또는 폴더에서 파일로 바뀌어도 새 파일 집합을 전달한다. 여러 파일을 쓰는 중 디스크 장애까지 원자적으로 복구하는 기능은 제공하지 않는다.

## 경계

공통 HTML은 텍스트와 URL을 검증하고, HTML 슬롯에는 명시적으로 신뢰한 출력만 받는다. 브라우저에서 React나 템플릿 엔진을 실행하지 않는다. 향후 프레임워크 래퍼가 필요해도 토큰과 구조의 정본을 복제하지 않는다.

검색 색인·라우팅·공개 승인·댓글 서비스·문서 메타데이터는 홈페이지에 남는다. ThinkFlow의 도형 배치와 DSL 의미는 ThinkFlow가 소유한다.

## 배포 경로

정본에서 ThinkFlow를 검증한 뒤 같은 디자인과 렌더러를 홈페이지로 전달한다. [공통 디자인 배포](distribution.md)에 실행·권한·실패 경계를 기록한다. 태그 릴리스는 별도이며 main 병합이 npm 발행을 뜻하지 않는다.

## 불변 조건

- 토큰 값과 CSS 역할은 정본에 한 번만 정의한다.
- 생성물은 원본에서 재생성하며 해시와 CI로 일치를 검사한다.
- 기존 소비자의 렌더러 계약은 사용처 확인 없이 삭제하지 않는다.
- 일반 텍스트와 검증된 HTML 슬롯을 구분한다.
- 실패한 검사, 변경된 소비자 사본, 앞서 바뀐 main은 자동으로 덮어쓰지 않는다.
- 불필요한 시안·감사 사본은 활성 소스나 배포물에 포함하지 않는다.
